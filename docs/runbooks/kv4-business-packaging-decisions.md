# KV4: Business & Packaging Gate — список решений

**Issue:** [#190](https://github.com/iurii-izman/voiceforge/issues/190).

Перед коммерческим распространением нужно зафиксировать решения по лицензии, дистрибуции и монетизации. Ниже — решения, принятые по данным программы и философии проекта (local-first, privacy, open core). При изменении политики обновить этот файл и при необходимости переоткрыть #190.

---

## 1. Лицензия и использование

- [x] **Лицензия кода:** оставить **MIT** (уже в pyproject.toml; соответствует open, local-first, минимальным ограничениям).
- [x] **Коммерческое использование третьими лицами:** **разрешено** (MIT явно разрешает коммерческое использование и распространение).
- [x] **Торговые марки и название:** использование «VoiceForge» в производных продуктах **допускается с условием** — атрибуция и отсутствие введения в заблуждение (типичная практика для open-source; при появлении товарного знака — уточнить формулировку).

**Решение:** MIT для кода; коммерческое использование разрешено; бренд «VoiceForge» — атрибуция и no-misrepresentation.

---

## 2. Дистрибуция

- [x] **PyPI:** **публиковать пакет публично** (CI и Trusted Publishing уже предусмотрены; соответствует открытой дистрибуции и установке через `pip`/`uv`).
- [x] **Desktop (Linux):** официально поддерживать **.deb, AppImage, Flatpak** (все три упомянуты в runbooks; Flatpak — путь в Flathub, AppImage — один файл, .deb — нативные пакеты).
- [x] **Исходный код:** **репозиторий остаётся открытым**; при появлении коммерческих надстроек — ядро (CLI, RAG, local STT, desktop shell) остаётся open; политика не меняется в сторону закрытия core.
- [x] **Updater (Tauri):** **включить при готовности** подписи артефактов и хоста обновлений; до того — в репо явно отключён (pubkey/endpoints пустые). Подпись и хостинг — владелец репо / CI; манифест в репо (`updates/update.json`) или свой endpoint.

**Решение:** PyPI публично; desktop — .deb, AppImage, Flatpak; код открыт; updater — включить при наличии подписи и endpoint, пока отключён.

---

## 3. Монетизация (по архитектуре: SaaS $20–50/seat/mo, self-hosted enterprise)

- [x] **Модель:** **open-source core + опциональные платные опции** (гибрид): бесплатное ядро (local-first, RAG, STT, desktop); монетизация — управляемый сервис (SaaS), enterprise self-hosted или премиум-фичи/квоты при появлении спроса (см. voiceforge-copilot-architecture.md, концепция A).
- [x] **Ценообразование (если платно):** ориентир из архитектуры — **SaaS $20–50/seat/мес**; self-hosted enterprise — по запросу (quote). Периодичность: месяц/год; лимиты при необходимости (пользователи, сессии) — определить при запуске платного контура.
- [x] **Self-hosted vs cloud:** **всё по умолчанию локально** (аудио, STT, RAG, embeddings); в облако при Hybrid/Cloud уходит только текст и вызовы LLM. Биллинг — только за облачные/управляемые сервисы (LLM API, будущий managed-хостинг); локальное использование бесплатно.

**Решение:** Бесплатный open-source core; платное — SaaS ($20–50/seat/мес) и/или enterprise self-hosted; биллинг только за облачную часть; local-first без изменений.

## 4. Упаковка и доставка

- [x] **Flatpak / Flathub:** **публиковать в Flathub** после стабилизации (offline-package.md, Flathub submission); до этого — сборка и манифест в репо, при необходимости свой репозиторий как промежуточный шаг.
- [x] **Enterprise / on-prem:** **отдельный контур при спросе** (Phase E: managed packaging = Accept later): Docker, .rpm/.deb для корпораций, SLA и поддержка — оформить при появлении запросов; не блокировать текущий open-source и desktop-релиз.
- [x] **Документация для платных опций:** при появлении платных фич — хранить в репо (раздел docs) или в отдельном репозитории/сайте; версионировать вместе с продуктом; открытая часть (установка, конфиг, API ядра) остаётся в основном репо.

**Решение:** Flathub после стабилизации; enterprise — отдельный трек по запросу; документация платных опций — в репо или отдельно, с версионированием.
